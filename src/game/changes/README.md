# The changes to the game

Everything the port changes in KSA itself, sorted by what it does for the player. A change is a hook, a class that
KSA Metal Hooks ([`../hooks/`](../hooks/)) apply to the game's C# code in memory when the game starts, a shader edit,
an `.edits` file the port's program ([`../../player/port-cli/`](../../player/port-cli/)) makes in the game's shader
sources when it makes the app, or both: a hook and the edit it needs sit side by side, named alike (`ShadowSearch.cs`,
`shadow-search.edits`). The changes KSA Metal's driver makes itself are in its README
([`../driver/`](../driver/)).

| Folder | Holds | Without them |
|---|---|---|
| [`fixes/`](fixes/) | what the game needs on the port: bugs fixed, and the port's part of the game (Restart, the documents folder, HDR, windows and UI coordinates); no row in the Mac Port tab | the game breaks: GPU hangs, crashes, clutter corrupted or striped, ring rocks missing, windows and panels misplaced |
| [`optimizations/`](optimizations/) | the same image, faster or in less memory: the rows of the tab's Optimizations and Memory | the game's own code and shaders, slower |
| [`features/`](features/) | a player's choice: the rows of Image, Extra Performance and Interface, the file's Experiments, the Resolution list, frame captures | the game's own behaviour; with its row off, a feature's edit changes nothing |

The hooks' project compiles every `.cs` here but `port/`, the code the port's program runs to write an edit
([`features/port/MilkyWay.cs`](features/port/MilkyWay.cs)). The port's program takes every `.edits` file, the folders
in the order fixes, features, optimizations, and in a folder the files in the order of their names; an edit that can't
be made (the code around it changed in a KSA update) prints `[WARN]` and leaves the game's code. How a hook finds what
it changes and what happens when a KSA update moved it is in the hooks' README ([The rule every hook
follows](../hooks/README.md#the-rule-every-hook-follows)).

## Fixes

| Hook | Tab row | File | How |
|---|---|---|---|
| `EditorClutter` | none (always on) | [`EditorClutter.cs`](fixes/EditorClutter.cs) | a game bug since KSA 5707: `PrePassRenderer.Render` draws the ground clutter's depth and normals, also in the Vehicle Editor, which keeps the clutter of the place it was opened from and draws none in colour. The light pre-pass lights those pixels and the enclosure's walls read that light by screen position: a ghost of the grass and trees. A prefix on `GroundClutterRenderer.RenderGroundClutterDepthNormal` returns while `Program.EditorFlag` is set; flight doesn't change |
| `ClutterOff` | none (always on) | [`ClutterOff.cs`](fixes/ClutterOff.cs) | a game bug since KSA 5707: `PlanetRenderer.RenderClutterDepthNormalPrePass` draws the ground clutter without asking whether there is any, as `RenderClutterDepthPrePass` beside it does. With the game's Ground Clutter off, the first frame near a world ends the game with a `NullReferenceException`. A prefix skips the pass when there is no clutter renderer |
| `ClutterResnap` | none (always on) | [`ClutterResnap.cs`](fixes/ClutterResnap.cs) | a game bug: ground clutter is placed with a world's streamed heights and normals (the slopes its terrain modifiers shape the heights with) and tinted with its streamed colours, but placed again only when the heights stream in finer (`CelestialTextureStreamer.GetHeightContentVersion`, read by `GroundClutterRenderer.AccumulateViewportCells` for the clutter drawn and `ClutterEcotypePhysicalData.UpdateGroundClutter` for the clutter vessels collide with). It keeps the slopes and tint of the moment the heights last changed, while the terrain takes the finer ones every frame: after a jump, rocks sit metres too low, many small ones under the ground, by how much depending on the frame the streamer finishes each map. Prefixes on both clear the remembered height version when the body's normals change version, and for the clutter drawn its colours too, so the game places its clutter again as it does for heights |
| `DescriptorRefresh` | none (always on) | [`DescriptorRefresh.cs`](fixes/DescriptorRefresh.cs) | a game bug: renderers rewrite a descriptor when `LastFrameUpdated < DeviceVector.FullLastFrameMoved`, comparing frame numbers, so a move of the vector or a new buffer for the shared pool after the rewrite in the same frame goes unseen, and that frame slot keeps an address inside a disposed buffer. The pool grows six times while part thumbnails are collected: with Loading Screen FPS Cap that is about 21 ms after the glow's first rewrite and the first present about 15 ms after it, so about 1 session in 10 misses it and every other frame comes out white. Postfixes on `DeviceHostSharedMemory.Resize` and `DeviceVector.Resize` set `FrameAllocated` and `FrameMoved` to a version that rises with every change |
| `Restart` | none (always on) | [`Restart.cs`](fixes/Restart.cs) | the popup's Restart starts the game's own executable again, which in the app is .NET's `dotnet` with no program: the game only quits. A transpiler replaces that call: it starts the app again through macOS (`open -n`, which hands the app its own environment: the game's, without what the port settings set, and `KSA_PORT_WAIT`, the game's process id), and the new launcher waits until this game has quit. A process the game started itself would not survive: when the app was started from the Finder, macOS ends what a quitting app leaves running. The new game reads the port settings as any start does |
| `Hdr` | none (always on) | [`Hdr.cs`](fixes/Hdr.cs) | the driver shows the game's HDR output with its HDR Paper White (Display) at the display's SDR white and tells macOS its HDR Peak Brightness ([Presentation](../driver/README.md#from-vulkan-to-metal)); the game keeps paper white to itself and sends the peak only when it rebuilds the swapchain: a postfix on `GameSettings.ApplyTo(GlfwWindow)`, where the game hands its Display settings to its renderer when it starts and at every Apply, passes `HdrOutput.PaperWhiteNits` and `PeakNits` to the driver (`ksaMtlHdrNits`). Without it, the driver takes the game's defaults, 200 and 1000 nits, and the peak the swapchain was built with |
| `UiViewSize` | none (always on) | [`UiCoordinates.cs`](fixes/UiCoordinates.cs) | the main view's size is the render size, smaller than the window below a render scale of 1, while what's drawn on it is in the window's points: a panel placed from it landed short of the screen's edge, and a mod's overlay sized from it clipped what it drew. While the frame's UI is drawn, and in mods' code at the frame's end, the size is the window's, for the game and mods alike; the render passes keep the render size. Code running at other times, such as a mod's patch on the views' update, sees the render size |
| `WindowOrigin` | none (always on) | [`UiCoordinates.cs`](fixes/UiCoordinates.cs) | ImGui's coordinates start at the desktop's corner, and a mod that takes them to start at the window's is right only with the window there: windowed, or on a display left of the main one, its overlay became an OS window of its own and what it drew was off by the window's position. The desktop now starts at the window's corner, for everything the game and mods read of windows and displays. Placing the main window itself keeps the real positions; a mod that moves it sets real positions but can only read relative ones (no listed mod does) |
| `ExtraWindows` | none (always on) | [`ExtraWindows.cs`](fixes/ExtraWindows.cs) | the game's extra windows (detached gauges, pop-outs) are created at macOS's floating level, and GLFW puts a fullscreen window above that, so a window detached in Fullscreen mode went behind the game. While the main window is at the floating level or above (Always on Top, Fullscreen), the extra ones are one above it |
| `KtxPaths` | none (always on) | [`KtxPaths.cs`](fixes/KtxPaths.cs) | a bug in the game's texture library: `Ktx.Loader.LoadFromFile` and `KtxTexture.SaveToFile` hand libktx the file's path as `Encoding.UTF8.GetBytes(path)`, without the zero that ends a C string, and libktx reads on past the array's end. A path whose length is a multiple of 8 ends where the next object in the .NET heap begins, and that byte isn't always zero: the path then names no file (seen as a stray 0x01 after the 56-byte paths of the parts' texture atlases). A transpiler gives both the same bytes with a zero after them |
| `Documents` | none (always on) | [`Documents.cs`](fixes/Documents.cs) | `STARMAP_INSTANCE_PATH` moves the game's documents folder, as StarMap does, also without StarMap (the benchmark's runs) |

| `LoadingPace` | Loading Screen FPS Cap | [`LoadingPace.cs`](optimizations/LoadingPace.cs) | while the game loads, `Loading.OnFrame` draws the loading screen after every step it reports (`Loading.Task`, `Loading.State`), and each frame waits for the display (the previous present, then a drawable): with Vsync, steps shorter than a refresh wait for one each. A prefix on the same has loading skip a far collection's acceleration structure: its finest level holds one without a handle, which clutter's sets take as none, and a prefix on `GroundClutterRenderer.GenerateGroundClutter` skips a body that holds it. Levels take 20-250 ms to build on a worker |

## Features

| Hook | Tab row | File | How |
|---|---|---|---|
| `ShadowSearch` | Simpler PCSS Shadows | [`ShadowSearch.cs`](features/ShadowSearch.cs) | with `simpler_pcss_shadows` on and the game's soft shadows (PCSS), each pixel searches the shadow cascades for blockers as far as the widest penumbra the sun casts, 1 m: hundreds of texels in the cascades near the camera, 16 taps that miss the GPU's caches. A prefix on `CascadedShadowMap.UploadCascades` puts a limit of 32 texels in the cascades' spare `_pad1`, which the port's shader edit ([`shadow-search.edits`](features/shadow-search.edits)) reads (0: the game's search). On an M5 at the Quality preset, with the edit that skips shadows where there is no sunlight already in, it takes about 8 % off the GPU time of grass (fur 32.4 -> 29.7 ms) and 3 % off views with shadows near the camera; the cockpit doesn't change. A penumbra is about 1/200 of its caster's height, so in the three nearest cascades a shadow cast from more than about 8, 30 or 85 m above can get a sharper edge; none of the views tried showed a change |
| `MilkyWayBake` | Baked Milky Way | [`MilkyWayBake.cs`](features/MilkyWayBake.cs) | with `baked_milky_way` on: `MilkyWay.frag` works out the Milky Way's dust clouds for every pixel of its band from the view direction alone, about 90 lookups of a noise texture each, 1-2 ms of a frame with much sky on an M5 (5-7 at the game's Milky Way Quality Ultra). The port's shader edit ([`milky-way-bake.edits`](features/milky-way-bake.edits)) moves the clouds into a function and writes `MilkyWayBake.comp` from the same file. A postfix on `MilkyWayRenderer.GenerateNoise` fills an 8192 x 512 strip of the clouds over the band (8 MB) and puts it in the noise's place, so the game binds it to the shader, which reads the clouds from it when its texture isn't square; a postfix on `BuildPipeline` fills it again when the quality (the clouds' octaves) changes. At the default field of view (50°) on a Retina display a texel of the strip is about 1.7 pixels, and the sky's pixels change by at most 1 of 255 in the views tried; the clouds are sampled from the strip, so zoomed in or in a larger window their finest grain can look softer. With the strip, at the Performance and Balanced presets, Milky Way Quality High costs what Low and Medium do (every view within 0.1 ms; Ultra not measured) |
| `TumblingPhysics` | Lighter Tumbling Physics | [`TumblingPhysics.cs`](features/TumblingPhysics.cs) | with `lighter_tumbling_physics` on: `PhysicsStates.ComputeTimestep`'s spin limit, (pi/6)^2 / w^2, gets its square root in free flight, at most 1/60 s and never shorter than the game's (a vehicle with ground or water contact keeps the game's step: its g-load decides whether it breaks, and depends on the step), so from about 4 rad/s on a tumble takes steps of up to 30 degrees and not ever shorter ones down to the 1 ms minimum (the square root alone lets falling pieces pass through the ground), and `KinematicStates.ClampVelocities`' spin cap goes from 5236 to 200 rad/s. These two and `KinematicStates.UpdateFromBepu` are inlined, so their callers call changed copies (reverse patches). With four rockets launched in turn at x32, physics substeps fall from 85,000-310,000 to 36,000-39,000 and the worst vehicle job from up to 324 ms to 71-76 ms. A rocket spun at 3, 8 or 30 rad/s falls and breaks up on landing as without it, with no piece through the ground in 24 landings; at 1000 rad/s it loses the spin above the cap at once |
| `CloudMarch` | Lighter Cloud March | [`CloudMarch.cs`](features/CloudMarch.cs) | with `lighter_cloud_march` on: `RaymarchCloud.comp` steps through a cloud layer at the layer's step size plus a share of the distance from the camera, up to its largest step (Earth's lower layer: 70 m + 0.006 x the distance, at most 1.5 km; the upper one 110 m + 0.0044 x, at most 4.5 km). A postfix on `CloudLayerRenderData.GetStaticLayerDataToWrite` makes the first two 1.5 times as large and keeps the largest step, so the march takes fewer steps where they stay below it: the lower layer within about 150 km of the camera, the upper one within about 650 km. On an M5, two games a side: at the game's own settings a launch 6 % faster, the rocket from above 4 %, Earth's cloud views 0.5-1.7 ms (the march itself is 4-6 ms of them); at the Balanced preset a launch 4 % and Earth's clouds over the sea 4 % faster; in still views about 0.6 % of pixels move by more than 8 of 255 against 0.2 % between two runs of the game's own. A larger largest step too changed the lower layer seen from orbit and saved nothing there; steps that grow once the ray has passed most of a cloud, as the game's smoke march does, broke up the march's dither on cloud tops |
| `CloudShadows` | Fewer Cloud Shadow Updates | [`CloudShadows.cs`](features/CloudShadows.cs) | with `fewer_cloud_shadow_updates` on: the slices `CloudShadowVolume.UpdateVolumeDensity` refreshes per frame, 24 and 8, become 6 and 2 |

## The shader edits' format

A file starts with its comment (`#` lines). Then steps, each started by a line `@@ <kind> <id> <shader>`, the shader's
path under `Content/Core/Shaders/`, and followed by its parts, each a line `@@ <part> [<value>]`. A part with text takes
the lines after it up to the next `@@` line, verbatim, without their trailing empty lines: no text ends with a line
break, and one that starts with an empty line starts with one. A comment between steps is a line `@@ # <text>`.

```text
@@ edit light-cluster-inverted-range Lighting/LightFineClusterCompact.comp
@@ what skipped tiles with an inverted depth range
@@ find
    uint binCount = maxBin - minBin + 1u;
@@ replace
    if (maxBin < minBin) return;  // macOS port: an inverted depth range would loop for billions of bins
    uint binCount = maxBin - minBin + 1u;
```

| Part | Of | Means |
|---|---|---|
| `@@ what <text>` | every step | what the edit did, as its `[FIXED]` line says; for a check, what is left out when it fails |
| `@@ needs <id>...` | every step | made only when those steps held (`[FIXED]` or `[OK]`); otherwise `[SKIP]` |
| `@@ find` | edit | the text to replace: exactly once in the shader |
| `@@ replace` | edit | its replacement; a `// macOS port:` comment says why, unless the change speaks for itself |
| `@@ earlier` | edit | what an earlier version of the port made of `find`: replaced too, in an app ported with it |
| `@@ done-if <text>` | edit | the shader holds this already (the game fixed it, or another wording of the edit): `[OK]` |
| `@@ done-if-line <text>` | edit | as `done-if`, for a line that starts with this text (after its indentation): not in a comment |
| `@@ contains [<shader>]` | check | text the shader, or another one, must contain |
| `@@ counts [<shader>] <word>=<n>[,<n>...]...` | check | how often each word may appear: the first number in the game's file, any of them once the file holds the shadow edits (`!PORT_SKIP_UNLIT_SHADOWS`) |

An edit goes, in this order: its replacement there already is `[OK]`; an earlier version's replacement there once is
replaced (`[FIXED] updated:`); `done-if` (or `done-if-line`) there is `[OK]`; `find` there once is replaced
(`[FIXED]`); anything else is `[WARN]`. Edits keep a shader's line endings (CRLF) and every other byte. A **check**
makes sure the code that uses what an edit skips still reads as it does here; it prints only when it fails (`[WARN]`),
and the edits that need it are then skipped. A **code** step (`@@ code <id> <shader>`) is an edit the port's program
makes in code: `milky-way` ([`features/port/MilkyWay.cs`](features/port/MilkyWay.cs)) moves a whole block of the
shader.

## Writing a shader edit

1. Find the smallest text that identifies the place, exactly once in the shader.
2. For an edit that skips work, add a check of the code that uses what it skips, and make the edit need it: a KSA
   version that changed that code keeps the game's image.
3. For an edit that needs another (a declaration), make it need that one: without it the shader would not compile.
4. Port the game into a test app and run it again: the first run prints `[FIXED]`, the second only `[OK]`.
5. When an edit's replacement changes, keep the old one as `@@ earlier`, so an app ported with it gets the new one.
